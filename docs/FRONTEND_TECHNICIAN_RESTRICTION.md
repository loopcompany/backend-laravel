# محدودیت دسترسی تکنسین در اپلیکیشن

پنل ادمین می‌تواند دسترسی تکنسین را با یکی از سه دلیل مشخص تعلیق کند. تاریخ و ساعت شروع تعلیق در پنل ثبت می‌شود. رفع تعلیق فقط با اقدام ادمین انجام می‌شود.

## پاسخ API

ورود `POST /api/technician/login` با رمز درست برای تکنسین معلق، `403` برمی‌گرداند. درخواست‌های احراز هویت شده با توکن همان تکنسین نیز `403` برمی‌گردانند. بدنهٔ پاسخ:

```json
{
  "success": false,
  "message": "حساب کاربری شما غیرفعال شده است.",
  "error_code": "ACCOUNT_DISABLED",
  "restriction": {
    "title": "صفحه محدودیت یا غیرفعال شدن",
    "reason": "امتیازات و نظرات منفی زیادی نسبت به قبل دارید.",
    "instruction": "جهت بازگشت به شرایط عادی لازم است ظرف مدت ۲۴ ساعت، به‌صورت حضوری به لوپ مراجعه فرمایید.",
    "suspended_at": "2026-09-29T12:00:00.000000Z"
  }
}
```

`reason` همان دلیلی است که ادمین انتخاب کرده است. در رکوردهای قدیمی که دلیل ندارند، متن عمومی جای آن می‌آید. `suspended_at` زمان شروع تعلیق به فرمت ISO 8601 است و ممکن است برای تعلیق‌های قدیمی `null` باشد.

## رفتار فرانت

1. اگر `error_code` برابر `ACCOUNT_DISABLED` بود، صفحهٔ محدودیت را باز کنید؛ این پاسخ را مانند خطای رمز عبور نمایش ندهید.
2. بالای صفحه علامت ضربدر قرمز و عنوان `restriction.title` را نشان دهید. زیر آن `restriction.reason` و سپس `restriction.instruction` را در کادر راست‌چین نمایش دهید.
3. در صورت نیاز زمان `suspended_at` را با تقویم شمسی و ساعت محلی نمایش دهید. زمان API به UTC است.
4. تا وقتی این وضعیت برقرار است، مسیرهای اصلی اپلیکیشن را باز نکنید. پس از رفع تعلیق توسط ادمین، توکن قبلی همچنان معتبر است؛ یک درخواست جدید دیگر پاسخ محدودیت نمی‌گیرد.
5. `401` و خطاهای دیگر را جداگانه مدیریت کنید. بعد از حذف تکنسین یا تغییر رمز، توکن‌های قبلی باطل می‌شوند و پاسخ `401` می‌گیرند.

رمز فعلی تکنسین در دیتابیس فقط به‌صورت هش نگهداری می‌شود. پنل به جای نمایش آن، امکان تعیین رمز جدید را دارد.
