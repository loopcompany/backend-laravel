# مدیریت زبان و ترجمه

در پنل مدیریت، گروه «زبان و ترجمه» دو صفحه دارد: «زبان‌ها» برای تعریف و فعال‌سازی زبان، و «ترجمه‌ها» برای ویرایش متن‌های هر برنامه. فارسی زبان معیار است و متن‌هایش قابل ویرایش هستند. فارسی حذف یا غیرفعال نمی‌شود. اگر ترجمه‌ای برای زبان انتخاب‌شده خالی باشد، متن فارسی نمایش داده می‌شود.

برای افزودن زبان، شناسهٔ استاندارد مثل `fr`، `ar` یا `zh-CN`، نام، نام بومی، جهت نوشتار و ترتیب نمایش را تعیین کنید. زبان جدید ابتدا غیرفعال است؛ پس از آماده‌کردن ترجمه‌ها آن را فعال کنید. فهرست زبان‌های اپ کاربر، ویندوز، اپ تکنسین و وب‌سایت از همین تنظیمات دریافت می‌شود.

متن‌ها در سه فرهنگ جدا هستند: `customer` برای اپ کاربر و ویندوز، `technician` برای اپ تکنسین و `website` برای سایت. شناسهٔ متن باید ثابت بماند؛ برای تغییر عبارت، «متن معیار فارسی» یا ترجمهٔ زبان مقصد را ویرایش کنید. متن‌ها عمومی هستند؛ اطلاعات حساب، رمز، کلید سرویس یا اطلاعات سفارش را در فرهنگ ترجمه وارد نکنید.

صفحهٔ ترجمه‌ها ورود و خروج JSON سازگار با i18next دارد. ساختار تو در تو و کلیدهای مسطح پذیرفته می‌شوند؛ برای نمونه:

```json
{
  "orders": {
    "count_one": "{{count}} commande",
    "count_other": "{{count}} commandes"
  }
}
```

ابتدا کلیدهای فارسی را تعریف کنید و سپس فایل زبان مقصد را برای همان برنامه وارد کنید. متغیرهایی مثل `{{name}}`، `{{count}}` و `{{value0}}` باید در ترجمه باقی بمانند؛ ورود ناقص متغیرها رد می‌شود و کل عملیات ورود به‌صورت یک تراکنش انجام می‌شود. خروجی JSON مسطح است و همان شناسه‌های i18n را حفظ می‌کند.

تغییرات از کانال عمومی WebSocket به برنامه‌ها اعلام می‌شوند و فرهنگ فعال دوباره دریافت می‌شود. در این کانال فقط شمارهٔ بازبینی ارسال می‌شود. سفارش‌ها، کاربران و پیام‌های خصوصی همچنان کانال احراز هویت‌شدهٔ خود را دارند. تغییر ترجمه فرم یا مسیر جاری کاربر را از نو ایجاد نمی‌کند. در قطع ارتباط، فرهنگ ذخیره‌شدهٔ محلی و سپس متن‌های همراه برنامه استفاده می‌شوند.

مجوزهای مشاهده، ایجاد، ویرایش و حذف زبان‌ها و ترجمه‌ها جدا هستند. ورود JSON به هر دو مجوز ایجاد و ویرایش ترجمه نیاز دارد. این مجوزها از صفحهٔ مجوزهای ادمین قابل واگذاری هستند.

## انتشار

پس از پشتیبان‌گیری و اجرای migrationها، فرمان `php artisan localization:seed` فرهنگ اولیه را وارد می‌کند. اجرای دوبارهٔ فرمان، ویرایش‌های مدیر را بازنویسی نمی‌کند. سپس مجوزها با `AdminPermissionCatalog::sync()` همگام شوند. تنظیمات موجود Reverb برای اعلام تغییرات استفاده می‌شوند.

آزمون‌های بک‌اند در `DynamicLocalizationTest` هستند. هر سه مخزن اپ، فرمان `npm run test:localization` دارند؛ آزمون‌ها قرارداد WebSocket، متغیرهای متن، تبدیل Babel، فاصلهٔ متن‌ها و قواعد Hook را بررسی می‌کنند.
